Where inventory matching should live

Daily Summary already has a product list, a mapping grid, and a verification pattern that blocks a summary until a person fixes it. Inventory tracking should reuse those, not add a new screen.

Recommendation: Version A

Edit the accounting-item match on Products and services. Keep Mapping for the accounts the adjustment posts to, plus a banner when products are still not matched. Store the match once, so both pages show the same result.

Version B is in the prototype so the two can be compared. It puts the same editor on a Products tab inside Mapping. That is workable, and it is the worse home for the job.

Why Products, not Mapping

  • A product row exists before any summary is imported. Mapping rows show up only after the first summaries, and only for the current grouping.
  • The Products table is already one row per sales product, with name, SKU, category, and the integration it was imported from. Mapping rows are groups, and they repeat per integration and currency.
  • People already come to Products to fix verification. Unmatched inventory is the same kind of problem: a product property that decides whether a summary can finish.

Placement, using what is already there

  • Accounting item column sits after Verification status. Both are a status of the product. Empty state is the same control Mapping uses for an unmapped account: “Select accounting item”.
  • Accounting item filter sits in the existing gray filter bar, next to Verification status, with All / Not matched / Matched. Apply and Reset filters stay where they are.
  • Find matching products is an outlined action beside Import. Add product stays the blue button. Auto-match does not save until the person reviews matched, several candidates, or no match.
  • Bulk bar replaces the column titles when rows are selected, the way Verify and Revoke verification already do. Clear match and Create in accounting join that bar. They do not get a second toolbar.
  • Not matched banner uses the same warning treatment as “Attention required” on Summaries. It says those quantities will not be adjusted, and offers Show not matched.
  • Row click still opens the product, as it does today. The accounting item is in that dialog as well as in the column.
  • Settings. Inventory tracking is a card above COGS on Products and services, the same card pattern as Unverified products. Turning it on switches the COGS rows off and disables them, with the reason on the card. The page note then changes from cost calculation to quantity posting.
  • Mapping keeps “Mappings list”, the account grid, and a banner that links to Products. Posting accounts (adjustment account, entity, warehouse, subsidiary) sit in a card above the grid, because they are account setup, not a product match.
  • Summaries keep the sync-status chip. A period can be Synced for the journal entry and Attention required for the inventory adjustment, with the reason under the documents.
  • Create in accounting is optional in the demo bar. On, it is a row link, a bulk action, a dialog for QuickBooks Online and Xero, and “Currently in development” plus “I need this” for Sage Intacct and NetSuite. Off, those controls disappear and matching stays manual or via Find matching products.

First run

Inventory tracking starts off until someone turns it on in Settings. The Products note and the banner explain that quantities are not posting yet. After it is on, unmatched products are visible immediately: warning banner, Not matched filter, and empty item fields. One product in the sample is already matched, so the column is not an empty mystery.

Sample data only. The layout follows the live Products, Mapping, Summaries, and Products and services settings screens.
